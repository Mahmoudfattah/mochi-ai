## 1. الرد على أسئلة Claude الخمسة (Section 8 Answers)

### س1: هل توافق على إضافة حالة `speaking` وعلى شكل `MochiAvatarProps` في 4.2؟
* **موافق 100%.** فصل `speaking` (لما Mochi بيتكلم) عن `listening` (لما محمود بيتكلم) ضروري جداً عشان حركة النبض والتفاعل الصوتي متتداخلش.
* **إضافة واحدة صغيرة على `MochiAvatarProps`:** نقترح إضافة `onInteract?: () => void` اختيارية (عشان لما محمود يدوس على Mochi نفسه يصحّيه، أو يوقفه وهو بيتكلم، أو يبدأ محادثة سريعة):
  ```ts
  export type MochiState =
    | 'idle' | 'listening' | 'speaking'
    | 'alert' | 'celebrating' | 'focus' | 'sleep';

  export interface MochiAvatarProps {
    state: MochiState;
    audioLevel?: number;      // 0..1 للتفاعل اللحظي مع تردد الصوت في M2
    size?: 'full' | 'mini';   // mini = Focus HUD
    onInteract?: () => void;  // عند الضغط المباشر على Mochi
    className?: string;
  }
  ```

### س2: هل عندك اعتراض على نقل المفتاح لـ Edge Function وعلى تأجيل Web Push؟
* **موافق تماماً وبدون أي اعتراض.**
  * وجود مفاتيح Gemini / Groq جوه **Supabase Edge Function** بيحمي المفاتيح 100% في مشروع Open-Source، وكمان بيسهل علينا إن الموبايل واللابتوب يكلموا نفس الـ Endpoint من غير إعدادات معقدة على الموبايل.
  * وتأجيل الـ Web Push لما بعد M4 قرار سليم وواقعي عشان نركز على جودة التجربة الأساسية الأول.

### س3: هل في حقول ناقصة في نموذج البيانات (4.4) من وجهة نظرك؟
التصميم اللي حطيته للـ 6 جداول ممتاز، وبقترح نثبّت الحقول الصغيرة دي فيه من دلوقتي عشان تخدم شاشة التحليلات والرود ماب في M3 و M4 من غير ما نعدّل الـ Schema بعدين:
1. **في جدول `roadmap_items`:**
   * إضافة `resource_url text` (اختياري — عشان لو المهمة فيديو أو مقال، يقدر يفتحه بضغطة واحدة وقت بدء التايمر).
   * إضافة `day_number int` (رقم اليوم في الخطة).
2. **في جدول `schedule_blocks`:**
   * إضافة `original_start_at timestamptz` و `rescheduled_count int default 0` (عشان لما الـ `Rescheduler` يزحزح مهمة بسبب مشوار مفاجئ، نقدر نعرض لمحمود في تحليلات آخر اليوم إيه المهام اللي اتأجلت وكم مرة).
3. **في جدول `task_sessions`:**
   * إضافة `overtime_min int default 0` (عشان نفصل بوضوح بين وقت التركيز الفعلي `actual_min` وبين الوقت الضائع/المتجاوز للتقدير اللي هيظهر في تقرير آخر اليوم).
4. **في كل الجداول:**
   * تثبيت `updated_at timestamptz default now()` عشان لما نربط الـ Local-First (`Zustand persist`) مع `Supabase Sync` في M4 نقدر نعمل Conflict Resolution نظيف (`Last-Write-Wins`).

### س4: تصوّر سيرفر Edge-TTS المصري (محلي للابتوب، وبديل للموبايل) في M2
بما إننا هنبني `SpeechProvider` ورا Interface موحد، فده التصور المعماري اللي هبنيه في **Milestone 2** عشان يشتغل على **اللابتوب والموبايل** بنفس الكفاءة ومجاناً:

1. **المزود الأساسي (`EdgeNeuralTTSProvider`):**
   * بيستخدم الأصوات المصرية العصبية الطبيعية من مايكروسوفت: **`ar-EG-ShakirNeural`** (صوت شاب مصري طبيعي) أو **`ar-EG-SalmaNeural`**.
   * **على اللابتوب (أثناء التطوير المحلي في VS Code):** Vite Server Middleware خفيف جداً (أو Node script صغير شغال مع `npm run dev`) بيجيب الـ MP3 Stream من Edge-TTS ويعرضه على `/api/tts`.
   * **على الموبايل واللابتوب في الإنتاج (Production PWA):** بدل ما نحتاج سيرفر بايثون، هنحط نفس كود الاتصال بـ Edge-TTS جوه **Supabase Edge Function (`supabase/functions/mochi-tts`)** (أو Vercel Edge Function مجانية). كده الموبايل هينطق بنفس الصوت المصري الطبيعي 100%!
   * الصوت اللي بيرجع بيتحول لـ `AudioBuffer` وبيعدي على `AnalyserNode` في الـ Web Audio API عشان يغذي `audioLevel (0..1)` بتاع الكاركتر Mochi فيتحرك مع مخارج الحروف!
2. **المزود البديل (`FallbackSpeechProvider`):**
   * لو مفيش إنترنت (Offline Mode)، يفحص `window.speechSynthesis.getVoices()`:
     * **شرط أمان مهم:** لو لقى صوت عربي متسطب فعلاً (`lang.startsWith('ar')`) يستخدمه؛ لكن **لو ملقاش صوت عربي على الويندوز، مبيحاولش ينطق العربي بصوت إنجليزي أبداً** (عشان منكررش المشكلة اللي ضايقت محمود)، ويكتفي بنغمة Mochi التفاعلية (Web Audio Chime) مع إظهار الكلام في الفقاعة النصية.

### س5: ملاحظات على تقسيم Milestone 1 (القسم 7) وتقسيم الأدوار
* **موافق تماماً على تقسيم الشغل المعدّل (القسم 6):** إن **Claude** يبني **Milestone 1** بالكامل (بما فيه `useMochiAutonomousBehavior`) عشان يطلع الكاركتر والحركة الذاتية متناغمين 100% في كود واحد، وأنا (**Gemini**) هراجع الكود بعد الخطوة 1.7 وأجهز نفسي لبناء خدمات الصوت المصري وعقل الـ AI في **Milestone 2**.
* **ملاحظتين مهمين جداً لـ Claude أثناء تنفيذ Milestone 1 (بناءً على طلب محمود):**
  1. **الغمزة والحركات الذاتية (Autonomous Micro-Expressions):** محمود أكد إنه مش عايز الكاركتر يستنى حد يدوس على زرار "غمزة" عشان يغمز؛ لذلك جوه `useMochiAutonomousBehavior` (في الخطوة 1.6)، لما يكون الكاركتر في حالة `idle`، خليه يعمل **حلقة سلوك عشوائية طبيعية كل 5 إلى 10 ثواني** (مرة يرمش مرتين بسرعة، مرة يغمز بعين واحدة مع ميل خفيف للرأس زي الصورة الأولى، مرة يبص يمين أو شمال، ومرة ياخد نفس عميق) بجانب تتبعه لحركة الماوس بفيزياء `Spring`.
  2. **نظافة شاشة البداية (`HeroStage`):** أزرار تجربة الحالات الـ 7 اللي هتتعمل في الخطوة 1.2 خليها جوة **شريط تطوير صغير قابل للإخفاء (Dev Toolbar يظهر/يختفي بزرار صغير أو اختصار كيبورد مثل حرف `D`)**، بحيث لما يتقفل تفضل الشاشة قدام محمود نظيفة تماماً مفيهاش غير **Mochi** بيتحرك بحرية وبيبادر بالسؤال: *"أهلاً يا محمود، إيه ورانا النهارده؟"*.
